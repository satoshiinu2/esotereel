# プラグイン開発ガイド: スクリプト API リファレンス

## 概要

プラグインの振る舞いは Rhai スクリプトで実装します。このドキュメントでは、スクリプトの読み込まれ方と、スクリプトから呼び出せる API を解説します。

スクリプトには次の 3 種類があります。

| 種類 | 置き場 | 呼ばれる場面 |
|------|--------|--------------|
| コンポーネントスクリプト | `components/` 配下（定義の `script` で指定） | 描画時に Scheduler が標準関数を呼ぶ |
| ツールバーボタンスクリプト | プラグインルート配下（定義の `script` で指定） | ボタンが押されたときにエントリ関数が呼ばれる |
| プラグイン共通スクリプト | プラグインルートの `script.rhai` | ホストが任意の関数を呼ぶ |

## 1. スクリプトのコンパイルとマージ

スクリプトは読み込み時にコンパイルされ、**基準ディレクトリ配下のすべての `.rhai` ファイルが 1 つにマージされます**。

- コンポーネントスクリプト: 基準は `components/` ディレクトリ
- ツールバーボタンスクリプトとプラグイン共通スクリプト: 基準はプラグインルートディレクトリ

マージの規則は次のとおりです。

- 対象ファイル自身が優先され、残りはパスの順にマージされます
- 同じ「関数名と引数の数」のシグネチャが異なるファイルに重複すると、読み込みエラーになります
- 引数の数が異なる同名関数のオーバーロードは許されます

つまり、同じ基準ディレクトリ内ではファイル間で関数を共有できますが、シグネチャの衝突には注意が必要です。

## 2. コンポーネントスクリプトと標準関数

コンポーネントが capability を宣言すると、Scheduler が対応する標準関数を `(ctx, props)` の 2 引数で呼び出します（capability と標準関数の対応は [コンポーネント定義リファレンス](components.md) を参照）。

標準プラグインの `components/video.rhai`:

```rhai
fn render_frame(ctx, props) {
    let tex = ctx.get_video_texture();
    let transform = props["std:video:transform"];
    ctx.render_video(tex, transform.as_mat4());
}

fn prefetch(ctx, props) {
    // TODO
}
```

### 2.1 引数

- `ctx`: 描画コンテキスト（RenderContext、第 3 節）。描画はこのオブジェクトへのメソッド呼び出しで行います
- `props`: そのコンポーネントが宣言したプロパティだけを含むマップ。**キーは名前空間付き ID の完全な文字列**です（例: `props["std:video:transform"]`）

Scheduler はコンポーネントごとにプロパティを抽出して渡すため、他コンポーネントのプロパティは見えません。

### 2.2 props の値の型変換

プロパティ値は Rhai の値に変換されて渡されます。

| プロパティの型 | Rhai での表現 |
|----------------|---------------|
| `bool` | bool |
| `int` | 整数（i64） |
| `float` | 小数（f64） |
| `string` / `enum` | 文字列 |
| `filepath` | 文字列の配列 |
| `color` | `r`, `g`, `b`, `a` をキーに持つマップ |
| `array` | 配列 |
| `map` / `group` | マップ（キーはメンバー名） |

## 3. 描画コンテキスト（RenderContext）

コンポーネントスクリプトの `ctx` は描画専用コンテキストです。次のメソッドが使えます。

| メソッド | 戻り値 | 説明 |
|----------|--------|------|
| `ctx.get_video_texture()` | 整数 | ホストが解決した映像ソースについて、現在のメディア時刻のテクスチャ ID を返します。未読み込み・フレーム未到着の場合は `-1` |
| `ctx.get_texture(path, start)` | 整数 | パスと開始秒を指定してテクスチャ ID を取得します。先読み幅は既定の 1 秒です |
| `ctx.get_texture(path, start, lookahead)` | 整数 | 先読み幅（秒）を明示する形式 |
| `ctx.render_video(tex, mat4)` | ― | テクスチャを変換行列つきで描画します |
| `ctx.render_video(tex, x, y, width, height)` | ― | テクスチャを指定位置・サイズで描画します |
| `ctx.set_transform(mat4)` | ― | ベース変換を置き換えます |
| `ctx.apply_transform(mat4)` | ― | ベース変換に行列を乗算します |
| `ctx.media_time()` | 小数 | このクリップの現在のメディア時刻（秒） |

テクスチャ ID が `-1` の場合や、対象の映像の寸法が未確定の場合、`render_video` は何も描画しません。未読み込みのパスを `get_texture` に渡すと読み込みが要求され、その場では `-1` が返ります。

映像ソース（どのファイルを読むか）は、ホストが `frame-provider` 能力を持つプロパティとそのメンバー（`media-source` 能力）から解決して `ctx` に設定します。スクリプトは `get_video_texture()` を使うことで、ソースの解決方法を意識せずに済みます。

### 3.1 変換行列（Mat4）

変換行列を作る方法は 2 つあります。

- マップに対する `as_mat4()` メソッド: `position`, `rotation`, `scale` の各キーに 3 要素の数値配列を持つマップから変換行列を生成します。video コンポーネントの `transform` プロパティはこの形式です
- 関数 `mat4_trs(position, rotation, scale)`: 3 つの引数はいずれも 3 要素の数値配列です

いずれも、回転は**度単位**で XYZ オイラー角として解釈されます。要素数が 3 でない、数値でない、有限でない値を含む場合はエラーになります。

## 4. アクションコンテキスト（ActionContext）

ツールバーボタンスクリプトとプラグイン共通スクリプトでは、描画用とは別のコンテキストが渡されます。エントリ関数は `ctx` の 1 引数で呼ばれます（標準プラグインの `buttons/undo.rhai`）。

```rhai
fn toolbar_undo(ctx) {
    ctx.network.undo();
}
```

### 4.1 ctx.network

| メソッド | 説明 |
|----------|------|
| `ctx.network.undo()` | 対象タイムラインの Undo リクエストを発行します |
| `ctx.network.undo(timeline_id)` | タイムライン ID（整数）を明示する形式 |
| `ctx.network.redo()` | 対象タイムラインの Redo リクエストを発行します |
| `ctx.network.redo(timeline_id)` | タイムライン ID を明示する形式 |

発行されたリクエストはスクリプト終了後にホストが回収し、クライアント側で実行した場合はサーバーへ送信され、サーバー側で実行した場合はそのまま処理されます。

### 4.2 ctx.set_property

```rhai
ctx.set_property(clip_id, "std:video:media/source_offset", 100);
```

- 第 1 引数: クリップ ID（整数）
- 第 2 引数: プロパティパス。名前空間付き ID をルートとし、メンバーを `/` でつなぎます
- 第 3 引数: 設定する値

値は次の規則でプロパティの値型に正規化されます。

- bool / 整数 / 小数はそのまま対応する型になります
- 文字列は bool → 整数 → 小数の順に解釈を試み、すべて失敗した場合は文字列として扱われます
- 配列とマップは要素ごとに再帰的に変換されます

## 5. 設定とツールバーの定義

### 5.1 settings.toml

プラグインが提供する設定項目を `[[fields]]` で宣言します。形式はプロパティスキーマと同じです（[コンポーネント定義リファレンス](components.md) 第 5 節）。

```toml
[[fields]]
key = "test_int"
category = []
label = "Test Int"
default = 0
kind = { type = "int", min = 0, max = 100 }
```

- `key` にはプラグイン ID が補われ、`std:test_int` のような名前空間付き ID になります
- 設定値はユーザーの設定ファイルに名前空間付き ID をキーとして保存されます
- プラグインが読み込まれる前に設定ファイルに書かれていた値は保持され、プラグインの読み込み後に適用されます

### 5.2 toolbars.toml と buttons

ツールバーボタンは `toolbars.toml` に `[[buttons]]` として宣言します。

```toml
[[buttons]]
id = "undo"
label = "Undo"
tooltip = "Undo"
action = { entry = "toolbar_undo", run_on = "client" }
script = "buttons/undo.rhai"
```

| フィールド | 型 | 必須 | 説明 |
|------------|------|------|------|
| `id` | 文字列 | ○ | ボタンのローカル ID |
| `label` | 文字列 | ○ | ボタンの表示ラベル |
| `script` | 文字列 | ○ | このボタン専用のスクリプト。プラグインルートからの相対パス |
| `action` | テーブル | ○ | `entry`（呼ぶ関数名、必須）と `run_on`（`"client"` / `"server"`、省略時は `"client"`） |
| `target` | 文字列 | ― | 属するツールバーの名前。省略時は `"timeline"` |
| `tooltip` | 文字列 | ― | ツールチップ。省略時は空 |
| `icon` | 文字列 | ― | アイコンの指定（任意） |

実行場所の違いは次のとおりです。

- `run_on = "client"`: GUI 側で、そのボタンの `script` でコンパイルされたスクリプトから `entry` 関数を実行します
- `run_on = "server"`: サーバーへ実行リクエストが送られ、サーバー側でプラグイン共通スクリプト（プラグインルート配下のマージ済みスクリプト）から `entry` 関数を実行します

どちらの場合も、エントリ関数は `ctx`（ActionContext）を 1 引数で受け取ります。`script` ファイルが存在しない場合、そのボタンのスクリプトは登録されず、実行時にエラーになります。
