# プラグイン開発ガイド: 概要

## 概要

Esotereel の機能拡張はプラグインで行います。このドキュメント群は、プラグイン開発者向けのガイドです。

- [概要](overview.md)（本書）: プラグインの全体像、構成、読み込みの仕組み
- [コンポーネント定義リファレンス](components.md): `components/` の TOML、capability、プロパティスキーマ、フック
- [スクリプト API リファレンス](script-api.md): Rhai スクリプトから使える API
- [チュートリアル: 新しいクリップ種別を追加する](tutorial.md): 標準プラグインを題材にした実践手順

## 1. 設計方針

プラグインまわりは、以下の分担を前提に設計されています。

- **描画 API は lib が定義する**: テクスチャ取得や描画コマンドなどの API は lib 側（`lib/src/plugin/`）が定義し、ホスト（core / GUI）が実行環境を提供します
- **描画そのものはプラグイン側が行う**: 「何を描くか」はプラグインの Rhai スクリプトが決め、ホストはその結果（頂点バッチ）を受け取って表示します
- **参照は ID のハードコードではなく能力（capability）経由で行う**: 本体はプロパティ ID やメンバー名を直接知らず、コンポーネントが宣言した capability から参照を逆引きします。プラグイン側もこの規約に従ってください（詳細は [コンポーネント定義リファレンス](components.md)）

## 2. プラグインのディレクトリ構成

プラグインは 1 つのディレクトリで構成されます。標準プラグイン（`plugins/std/`）の構成は次のとおりです。

```
<plugin_dir>/
├── manifest.toml       # プラグインのメタ情報（必須）
├── settings.toml       # 設定項目のスキーマ（任意）
├── clips/              # クリップ種別の定義（任意）
│   └── *.toml
├── components/         # コンポーネント定義とそのスクリプト（任意）
│   ├── *.toml
│   └── *.rhai
├── mixins/             # mixin 宣言とハンドラスクリプト（任意、読み込みのみ実装済み）
│   ├── *.toml
│   └── *.rhai
├── toolbars.toml       # ツールバーボタンの定義（任意）
├── buttons/            # ツールバーボタン用スクリプトの置き場（慣例）
│   └── *.rhai
└── script.rhai         # プラグイン共通スクリプト（任意）
```

`manifest.toml` 以外のファイル・ディレクトリはすべて任意です。存在しないものは空として扱われます。

配置場所は次の 2 か所で、配下の各サブディレクトリが 1 プラグインとして探索されます。

- アプリ同梱の組み込みプラグイン: インストールディレクトリ配下の `std_plugins/`
- ユーザープラグイン: ユーザーデータディレクトリ配下の `plugins/`

## 3. manifest.toml

プラグインのメタ情報を記述する必須ファイルです。

```toml
id = "std"
name = "The Standard Plugin"
version = "0.0.1"
```

| フィールド | 型 | 必須 | 説明 |
|------------|------|------|------|
| `id` | 文字列 | ○ | プラグイン識別子。すべての名前空間付き ID の接頭辞になります |
| `name` | 文字列 | ○ | プラグインの表示名 |
| `version` | 文字列 | ○ | プラグインのバージョン |

## 4. 名前空間付き ID（NamespacedID）

プラグインが提供するクリップ種別・コンポーネント・プロパティ・ツールバーボタンは、すべて `plugin_id:local_id` 形式の名前空間付き ID で識別されます（例: `std:video`）。

- TOML 内ではローカル ID だけを書き、読み込み時にプラグイン ID が補われます
- ローカル ID の途中に `:` を含めることもできます（例: プロパティキー `video:media` は `std:video:media` になります）
- 使用できる文字は ASCII 英字・数字・`.`・`_`・`-`（および区切りの `:`）です。これ以外を含む ID は読み込み時にエラーになります
- ID は全プラグインを通じて一意でなければなりません。クリップ種別やコンポーネントの ID が他のプラグインと衝突すると、インデックス構築時にエラーになります

## 5. 読み込みの仕組み

プラグインは `PluginLoader`（`lib/src/plugin/mod.rs`）が読み込みます。

1. 組み込み・ユーザーの両配置場所からプラグインディレクトリを探索する
2. 各プラグインを並列に読み込む。**1 つのプラグインの読み込み失敗が全体を止めることはなく**、失敗したプラグインはログに記録されて除外されます
3. 全プラグインのクリップ種別・コンポーネント定義・スクリプト・設定スキーマ・ツールバーをマージし、インデックスを構築する

実行時には、プラグインの追加読み込み（ホットロード）、再読み込み、アンロードも API として用意されています。

各定義ファイルの読み込み規則は共通です。

- `clips/` と `components/` は配下のすべての `.toml` ファイルがファイル名順に読み込まれます
- 同一プラグイン内で ID が重複するとエラーになります
- スクリプト（`.rhai`）はコンパイル時に周辺ファイルとマージされます。マージ規則は [スクリプト API リファレンス](script-api.md) を参照してください

## 6. クリップ種別とコンポーネントの関係

クリップ種別（`clips/*.toml`）とコンポーネント（`components/*.toml`）は役割が分かれています。

- **クリップ種別**: タイムラインに配置できるクリップの種類そのものの宣言です。定義は最小限で、プロパティは持ちません
- **コンポーネント**: クリップの描画・振る舞いとプロパティスキーマを提供する部品です

両者は **同じ名前空間付き ID で結びつきます**。クリップ種別 `std:video` のプロパティと描画は、同じ ID を持つコンポーネント `std:video`（ルートコンポーネント）と、その子コンポーネントが提供します。したがって、描画されるクリップ種別には、同名のコンポーネント定義が必要です。

コンポーネント定義の詳細は [コンポーネント定義リファレンス](components.md) を参照してください。

## 7. Mixin 宣言

`mixins/` ディレクトリには、他のプラグインが提供する関数（標準関数や lib の API）の呼び出しへ処理を差し込むための mixin 宣言を置けます。宣言は TOML の `[[mixins]]` 配列で記述し、`components/` と同じく `script` フィールドでハンドラスクリプト（`.rhai`）と関連付けます。

```toml
[[mixins]]
id = "logo-overlay"
target_fn = "render_frame"
at = "after"
script = "logo.rhai"
handler = "add_logo"
```

| フィールド | 型 | 必須 | 説明 |
|------------|------|------|------|
| `id` | 文字列 | ○ | 宣言のローカル ID。全プラグインを通じて一意である必要があります |
| `target_fn` | 文字列 | ○ | フック対象の関数名 |
| `target_component` | 文字列 | ― | 対象を特定のコンポーネントに絞る場合に指定します |
| `target_capability` | 文字列 | ― | 対象を capability で絞る場合に指定します。未知の capability 名はエラーになります |
| `at` | 文字列 | ○ | 注入位置。`before`（呼び出し前）または `after`（呼び出し後） |
| `priority` | 整数 | ― | 実行順（大きい方が先）。省略時は 1000 |
| `script` | 文字列 | ○ | ハンドラスクリプト（`mixins/` からの相対パス）。存在しないファイルを指すとエラーになります |
| `handler` | 文字列 | ○ | ハンドラ関数名 |

**実装状況**: 現在は読み込みのみが実装されています。宣言は読み込み時に検証され、対象関数ごとのフック表まで構築されますが、ハンドラの実行（dispatch）は未実装のため、宣言を置いても実行時の挙動は変わりません。
